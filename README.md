## 2. Найденные дефекты

### BUG-01. Принимается бронирование продолжительностью менее 30 минут

**Приоритет:** High — нарушается установленное ограничение минимальной длительности бронирования.

**Условия:** выбрана любая переговорная.

**Шаги воспроизведения:**
1. Выбрать любую переговорную.
2. Указать время начала — 08:11.
3. Указать время окончания — 08:12.
4. Отправить форму.

**Ожидаемый результат:** система отклоняет бронирование, поскольку минимальная длительность составляет 30 минут.

**Фактический результат:** бронирование успешно проходит.

Дефект проверен на всех трёх типах переговорных: малой, средней и большой.

### BUG-02. Принимается бронирование продолжительностью более четырёх часов

**Приоритет:** High — нарушается установленное ограничение максимальной длительности бронирования.

**Условия:** выбрана любая переговорная.

**Шаги воспроизведения:**
1. Выбрать любую переговорную.
2. Указать время начала — 08:11.
3. Указать время окончания — 16:12.
4. Отправить форму.

**Ожидаемый результат:** система отклоняет бронирование, поскольку его длительность превышает четыре часа.

**Фактический результат:** бронирование успешно проходит.

Дефект проверен на всех трёх типах переговорных.

### BUG-03. Можно забронировать уже прошедшее время

**Приоритет:** High — пользователь может создать бронирование на время, которое уже прошло.

**Условия:** бронирование на текущий день.

**Шаги воспроизведения:**
1. Указать время начала — 09:47.
2. Указать время окончания — 10:20.
3. Отправить форму в 09:48.

**Ожидаемый результат:** система не принимает бронирование, поскольку время начала уже прошло.

**Фактический результат:** форма успешно отправляется.

![BUG-03 — бронирование на прошедшее время](https://github.com/user-attachments/assets/b85f264e-9581-466e-95a9-e01c5cd843f3)

### BUG-04. Форма принимает некорректный формат электронной почты

**Приоритет:** Medium — пользователь может создать бронирование с некорректным адресом электронной почты.

**Условия:** открыта форма бронирования переговорной.

**Шаги воспроизведения:**
1. Заполнить обязательные поля корректными значениями.
2. В поле электронной почты указать `user..name@example.com`.
3. Отправить форму.

**Ожидаемый результат:** система отклоняет адрес с двумя последовательными точками в локальной части и отображает сообщение об ошибке.

**Фактический результат:** форма принимает некорректный адрес электронной почты и успешно создаёт бронирование.

## 3. Автоматизированное тестирование

Для автоматизации использованы **Python, pytest и Playwright**.

Подготовлены три теста:
- позитивный сценарий успешного бронирования;
- негативный сценарий проверки некорректных данных;
- проверка найденного дефекта BUG-01.

Также используется готовый smoke-тест из предоставленного каркаса. Он не входит в три теста кандидата.

Для BUG-01 используется `xfail(strict=True, reason="BUG-01: ...", raises=AssertionError)`. Тест проверяет ожидаемое поведение приложения, а не закрепляет существующий дефект как норму.

## 4. Docker и контейнеризация

Для изолированного запуска автотестов подготовлены:
- `Dockerfile` на базе официального Playwright Python image;
- `compose.yaml` для запуска тестов через Docker Compose;
- передача `BASE_URL` через переменные окружения;
- сохранение JUnit XML-отчёта через Docker volume.

Проверен запуск тестов в контейнере без необходимости отдельно устанавливать Python и браузер на машине запуска.

## 5. Запуск автотестов

Для запуска требуется Docker с Docker Compose v2.

Из корня репозитория выполните:

```bash
docker compose run --build --rm tests
```

Команда соберёт тестовый образ и запустит smoke-тест вместе с тестами кандидата.

Результаты сохраняются в каталоге `artifacts/`:

- `artifacts/junit.xml` — JUnit XML-отчёт;
- `artifacts/browser/` — материалы диагностики при падении тестов, если они сформированы.

Для запуска с другим URL можно передать переменную окружения:

```bash
BASE_URL=https://example.com docker compose run --build --rm tests
```

### Альтернативный запуск без Docker

Если Docker недоступен, можно установить зависимости вручную:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest
```

## 8. Вопросы и допущения по требованиям

1. Не уточнено, допускается ли бронирование переговорной на текущую дату, если время начала ещё не наступило. Принято допущение, что бронирование разрешено при условии, что выбранное время не находится в прошлом.

2. Не указано, должны ли запрещаться пересекающиеся бронирования одной переговорной. Проверка этого правила не выполнялась.

3. Не определены дополнительные ограничения к формату рабочего email, кроме требования валидного адреса.

4. Согласно требованиям, данные формы не отправляются на сервер и не сохраняются после перезагрузки страницы. Поэтому проверка ограничена клиентской валидацией и отображением результата.

## 9. Проверенные области и ограничения

Проверены:
- отображение формы и основные пользовательские сценарии;
- обязательность полей;
- ограничения вместимости переговорных;
- ограничения длительности бронирования;
- проверка даты и времени;
- базовая валидация электронной почты;
- отображение результата бронирования;
- отсутствие сохранения данных после перезагрузки;
- отдельные проверки адаптивности и отображения пользовательского ввода.

Ограничения:
- серверная обработка и сохранение бронирований отсутствуют согласно условиям задания;
- проверка пересечения бронирований не проводилась из-за отсутствия соответствующего требования;
- автоматизированное покрытие ограничено тремя тестами кандидата и готовым smoke-тестом.
